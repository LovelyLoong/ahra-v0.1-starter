# Goal

Make the acceptance-first governed dynamic kernel the explicit project direction without pretending unimplemented capabilities already exist.

# Scope

- Add ADR-0007 and the new architecture/policy documents.
- Update README, AGENTS read order, docs indexes, and roadmap references.
- Create an authority map stating which document owns each live concept.
- Mark conflicting or duplicate documents proposed, future, legacy, deprecated, or superseded.
- Ensure README separates current implemented behavior from target architecture.
- Add component lifecycle rules to the normal Agent read path.

# Non-goals

- Do not change runtime behavior.
- Do not delete old implementations.
- Do not claim dynamic planning is operational.

# Acceptance criteria

- [ ] ADR-0007 is accepted or explicitly rejected with a replacement decision.
- [ ] Exactly one active document owns the dynamic execution architecture, verification model, PlanIR, and component lifecycle concepts.
- [ ] README and AGENTS distinguish implemented current paths from proposed target paths.
- [ ] Superseded documents remain traceable but are excluded from default read order.
- [ ] Documentation lint detects duplicate active authority IDs or broken index links.
- [ ] All existing repository checks pass or preserved baseline blockers remain unchanged and documented.

# Verification method

- python scripts/check.py
- python scripts/lint_awkp.py
- git diff --check
- documentation authority/index lint

# Required evidence and handoff

- Publish an implementation/change report with exact files, contracts, migrations, known limitations, and unresolved items.
- Preserve deterministic command outputs or structured summaries with content digests.
- Map every acceptance criterion to one or more Evidence IDs.
- Record the producer Agent Release, Context Manifest, workspace/branch, base commit, and final commit or rejected patch.
- Create an immutable Handoff with one exact next action when blocked, failed, paused, or returned for changes.
- The producer must not mark this task completed; an independent verifier and EvidenceGate decide completion.

# Rollback and compatibility

- Do not silently overwrite released contracts or historical events.
- Use a new schema version when field meaning changes or compatibility is broken.
- Keep compatibility adapters until the task explicitly authorizes their removal.
- Any rollback must preserve Artifact/Evidence references and explain state projection changes.
